1.5 已确认的执行细则（自决，不占决策题）

  • 需求级写锁：同一时刻一个写会话，其余会话只读 / 评审；写锁带租约与过期释放。
  • 会话 header cwd 必须精确等于需求目录（否则 attachSession 拒绝、会话变 Ungrouped）；AI 后续用 working_directory(cd) 进入 worktree 不改变归属。
  • 需求上下文用 agent.inject() 显式注入，不依赖 AGENTS.md 目录链；$DSH_HOME/AGENTS.md 只放平台红线。
  • 平台侧自建能力：三类平台角色、四类阶段角色、一人多身份、一账号多项目、批量导入 / 指派 / 状态机，沿用设计文档 §6，D17 原型必须画出相应页面。
  • 服务账号拆权：git push 凭据、模型网关凭据、审批代答凭据分离托管，密钥轮换 + 逐次调用审计写 PG。
  • BFF 补强：DSH 只绑 loopback + 主机防火墙拒绝外部直连；Token / Cookie 有效期改短并按需轮换；第二道闸（RemoteAccessPolicy）定为 PoC 强制验收项。
  • 故障路径：崩溃后按 session 单写者所有权恢复写句柄；repair 失败即标记需求不可用并告警；revert MR 被拒保持环境现状并上报；syncer 校验基线 commit 签名；多仓库一组 MR 允许部分成功但必须聚合告警。
  • 供应链 P0：发布包剔除 claude-code-mods 相关实验插件及 Claude Code 平台 payload，不依赖其 identity-scoped 授权；MPL-2.0 LibreOffice 套件保留对应源码与 NOTICE 可得路径。
  • 品牌：「DeepSeek Harness」是注册商标，不用作项目名；只作事实性描述（如「基于 DSH 构建」），建议用缩写 DSH。

3.2 必须携带的残余风险

R-A（C1，用户明确不追认）：无 Docker 档下，AI 子进程与 sources/ 在同一台主机、同一内核，隔离依靠 OS 用户 / 目录权限 + DSH 自带 bwrap / Seatbelt + rdws-policy 路径守卫。而 SAFETY.zh.md 明确「沙箱、审批与权限控制不保证隔离」「不得作为不可信工作负载唯一的安全控制」。用户未追认「生产 / 不可信负载必须启用 Docker 强隔离档、PoC 验收含该档」这一修订，因此：无 Docker 档仅作为开发与功能验证档，不作为生产或不可信工作负载的安全边界；面向真实项目组或生产数据时的隔离强度由部署方自行评估并承担风险，PoC 不覆盖生产档验收。台账 v3 撤回 v2 里越界的「不可推翻前置」表述，恢复自洽。
R-B（D2 口径）：关闭 dsh_session_log 与遥测只是移除附加字段与旁路通道，模型请求本身仍携带源码片段、命令输出与文件内容。若部署方选公网供应商，等同于源码出企业边界。这是用户明确选择的「平台不预设限制」的后果，不是遗漏；平台不代为判断合规性，但必须在部署清单中显著登记并要求数据合规确认。抓包验收保留为部署方检查项。
评审已确认非缺陷：D9↔D26、D7↔D26 属「当前形态 vs 未来上界」，非互斥；「默认内网网关模板 vs 不预设限制」是示例而非硬限；全 TS 单栈与长期环境分支属取向。上轮报告 §2 的其他 P0（MIT / 商标 / 第三方依赖 / 会话日志上传 / 遥测 / 锁版本）均已落到执行细则。
