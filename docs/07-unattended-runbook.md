# RDWS 无人值守研发运行手册

适用范围：在本仓库运行的无人值守研发轮（定时任务、`/goal`、连续推进提示词驱动）。在场交互开发不使用本手册，直接按 `AGENTS.md` 执行。触发提示词只写入口、红线与本次授权；选取阶梯、门禁与留痕以本手册为唯一事实源。

## 1. 准入（先于一切）

- 每轮第一个动作是取得运行资格：

  ```
  python3 ~/.agents/skills/sop-unattended/scripts/run_guard.py acquire \
    --item <工作项编号> --paths <改动路径...> --max-hours 4 --label <备注>
  ```

  改动路径拿不准就用 `--exclusive`。退出码 3 = 被拒：零产出、安静收尾，只留一行结论。

- 状态在 `<git 公共目录>/.sop_sessions/`（即 `.git/.sop_sessions/`），所有 runner 与 worktree 共享。
- 每阶段结束、长命令前后用 `heartbeat --run-id <id>` 续期；返回冲突（退出码 4）说明资格已易主，立即停止改动并报告。
- 收尾（含中途停止）必须 `release --run-id <id> --changed <实际路径...>`；中断残留的 `rdws-authority-*` Docker 夹具容器可用 `docker rm -f` 清理。

## 2. 入口与选取阶梯

1. 读 `AGENTS.md`（导航）→ `.git/.sop_sessions/handoff.md` 与 `pending.md`（当前态）→ 最近 `runs/*.log`。
2. 按顺序取第一个触发条件满足的项，写明选取理由；全部落选就报告逐档理由后收尾，不为产出发明工作：
   - handoff「剩余工作」中标注可在本机独立完成、验证的项；
   - `pending.md` 中无外部依赖的工程项；
   - `docs/05-development-backlog.md` 中前置已满足且现有授权与具名资源内可验证的项。
3. 当前已知排除项（触发条件未满足）：T08（T07 未解锁）；T14 正式登记（等平台审核冻结）；T16 正式验收（等具名快照、DBA 凭据与用户走查）；T07 Native Read 回环（缺可独立证明的首写保权机制，等裁决）；一切需要真实模型供应商、具名部署、生产配置或用户走查的验收。

## 3. 切片纪律

- 同一时刻只开一个主工作项；一项等于一个可独立验证的最小功能切片（实现 + 测试 + 工程文档证据段 + 清单同步，沿用既有会话惯例）。
- 改权限、数据模型或公共契约（R2/R3）先在 `docs/02-directory-and-engineering-design.html` 补小节与判据，再实现。
- 界面用 TDesign 与 RDWS 主题令牌，界面中文、标识符英文；迁移先改 schema、`pnpm db:generate` 审阅后 `pnpm db:migrate`，不改已应用迁移。
- 遇无人可答的产品/验收级决策：记入 `.git/.sop_sessions/pending.md`，不自决、不提问、不阻塞下一项。技术分叉按仓库既有证据自决并记录理由。

## 4. 验证门禁（提交前必须全绿，只记本轮实跑证据）

1. 受影响焦点测试：`pnpm test <受影响测试文件>`。
2. 整仓回归：`pnpm test`（整仓；条件跳过如实记录，不得当作通过）。
3. 静态：`pnpm typecheck && pnpm lint && pnpm format:check && pnpm build && pnpm validate:baseline`。
4. 界面旅程变更另跑 `pnpm test:e2e`（跑前确认 5317/3303 端口未被占用）；`pnpm test:web-live` 一律不跑。
5. 修复轮改到哪个模块，提交前必须重跑该模块的专属用例文件，不得沿用修复前的邻域证据；整仓绿不替代本项（2026-11-24 教训：Read 回环回归曾穿过两轮评审确认、被整仓门禁抓到）。暂无法本地跑的套件（如受管浏览器）须在诚实边界明示并列为待复核项。

- 整仓回归复用本机 Compose 项目 `rdws-night-902ec79d835f` 的 PG（127.0.0.1:53489，保留隔离数据）；不存在时按 `scripts/` 内既有命令重建。
- 退出码 0 与「通过」分开核对；数字从工具输出原样复制，不虚构、不缩位。

## 5. 智能体团队分工

- 每个功能切片默认开一个小团队：实现成员 + 独立评审成员（全新上下文冷读 diff、对照验收判据与工程文档判据）。评审 `verdict=pass` 才进入提交；`needs_revision` 修复后重评，3 轮未过停该项、剩余发现记 `pending.md`。
- 测试由实现成员实跑；评审成员复核证据（命令、退出码、关键数字），不重复跑慢套件。
- 纯文档、清单同步等轻量改动可由主会话直接完成，不强制开团；团以 `approval=automatic` 创建（由触发提示授权），收尾后 `delete` 归档。

## 6. 提交与留痕

- 每完成一个完整已验证功能即本地 `git commit`（英文 Conventional Commits）；必需验证未通过或评审有阻塞项时先解决，不按已完成功能提交。
- 只在本地 `main` 开发，不建长期分支；本地提交后直接推送 `origin/main`（2026-11-23 用户常设授权，单人产品不开 PR）；本地提交与用户侧验收分开记录，清单如实保留待验收状态。
- 提交同一功能所需的代码、测试、迁移、文档与清单同步一起归集；无关改动保留不混入。
- 留痕：更新 `docs/05-development-backlog.md` 与工程文档证据段；`runs/YYYY-MM.log` 追加一行；`handoff.md` 整体覆盖为最新交接（单文件覆盖，不按日期留副本）。
- 时间盒（单项约 90 分钟）到点、上下文吃紧或一项完成时：提交已验证成果、覆盖 `handoff.md`、释放准入，再领下一项。

## 7. 红线

- 不开 PR、不部署、不改生产配置；推送随本地提交执行（2026-11-23 用户常设授权）；不翻转用户侧验收状态；不改已应用迁移。
- 不调用真实模型供应商、不访问任何具名外部环境；所有验证用一次性隔离容器与本机回环。
- 凭据只进本机环境，不入代码、日志、提交说明与报告。
- 发现本手册缺陷：记入 `pending.md`，不在运行中自改手册。
