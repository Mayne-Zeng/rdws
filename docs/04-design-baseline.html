2可访问性实测报告

方法：headless Chrome 通过 CDP 打开真实页面，逐视图注入 WCAG 相对亮度公式（0.2126R + 0.7152G + 0.0722B，sRGB 线性化），对每个含直接文本节点的可见元素取计算样式前景色、向上合成不透明背景色，计算对比度。普通文字阈值 4.5:1，大字号（≥24px，或 ≥18.66px 且 ≥700）阈值 3:1。每视图最多采样 500 个文本元素；明 / 暗主题各跑 16 视图。

结论：WCAG AA 对比度全通过。Light 1461 样本 / 0 失败 / 最低 4.84:1；Dark 1461 样本 / 0 失败 / 最低 5.49:1。设计系统页原先「≥4.5:1」的自述，现在有了逐视图实测证据。暗色主题 16 视图零横向溢出。

5交接边界与验证

  • 三条硬约束：① 单一 --content-w:960px 与 --gutter:24px，任何新页面 / 面板不得再引入第二档宽度；② 交互控件走 --control-h（30 / 40px），新增可点击元素必须同步判据；③ 入口跟随作用域，跨级操作回自己作用域的页面。
  • 改动边界：本轮改 demo/rdws-workbench.html 的 P1/P2 修复与会话区调整（项目卡快捷新建、会话信息收拢、一步新建），以及本文件；台账 v3 决策正文、R-A / R-B 残余风险口径未动。§4 的发现项已按清单全部落地并重测。
  • 验证方式：本文件由 /tmp/rdws-baseline-collect.js 与 /tmp/rdws-heights-locate.js 的实测 JSON 生成；文档本身已用真实浏览器打开验证渲染与关键文案。任何 Demo 改动后，重跑这两个脚本并重新生成本文件。
  • PoC 交界：台账 §5.2 的四项验收（cwd 归属、sources 零写入、≥5 会话 resume/fork/replay、rdws/* push + MR 映射闭环）属于工程验证，不在本文件范围；本文件提供的是它们依赖的界面契约与视觉验收口径。
