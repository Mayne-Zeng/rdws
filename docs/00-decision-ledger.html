8.1 范围与替代关系

编号当前有效决定替代 / 边界
I2最小真实 Web 工作台；验收一项目、一需求、一仓库、一个非生产目标环境，至少五个会话，包含人工 MR 合入后的真实结果回写。项目、账号、角色、运行配置预置；需求在 Web 创建。实际部署、部署批准、归档清理、HA、多机、Tauri、多环境编排、完整测试 / Bug 链路延后。
I2-STATE需求开发负责人按 I6-STAGE 通过 Web 按钮或菜单选择目标阶段，允许跳转、回退并逐次留痕；成员推进本人子任务状态。主状态与未来的测试、GitLab 合入事实分开记录。本轮不提供手打指令或对话写入。撤回旧阶段人员审批及其指派、超时和重审条款；GitLab MR 审批继续按仓库规则执行。
I2-AUTH本地预置账号、关闭公开注册。普通成员按需求参与关系读取；项目管理员仅在授权项目有管理读取权限；平台管理员业务权需显式授予。代码写需要当前有效开发分派、本人会话及需求独占写权限。角色在当前项目 / 需求范围内合并，不能借另一项目角色越权；管理身份不自动取得代码写权限。
I3-TASK需求可有多个开发成员，一个开发负责人。子任务单一负责人，默认需求开发负责人；需求经理 / 项目管理员初始拆分分派；开发负责人后续维护全部子任务，并在已有需求开发成员内改派。新增子任务、参与与分派历史模型；分派不是扩大需求成员集合的入口。
I3-WRITE一个需求共享一组工作树，同一时间仅一个实际写会话。旧写任务及其子进程停稳后再交接；不能确认停止时保持只读。恢复与 fork 重验当前权限，测试人员会话代码只读。租约过期不等于进程停写；不实施子任务物理隔离、二级并行工作树。Plan 仅软指引，权限必须由平台、DSH 与文件 / 进程限制共同执行。
I3-CONTEXTWeb 业务动作统一鉴权、防重、短事务更新目标字段及留痕，不要求用户处理 revision 冲突。当前每个新推理步骤读取最新上下文；恢复执行亦适用同一规则。取得写权限前刷新是后续单写切片要求。已发出的模型请求不会被更新；静态 AGENTS.md 与 demand.yaml 不是动态状态权威。当前不向模型暴露写入工具。
I3-DELIVERY交付快照不可变；分别记录历史候选、当前候选及实际合入快照。需求原提交、集成 cherry-pick 提交、merge / squash SHA 分开。更新可沿用未合入 MR；已合入后发增量 MR。仅平台受控 push 到 rdws/*，环境保护分支走 MR 人工合入；不自动批准、合入、强推或回退。
I4-UI独立自绘业务界面，尽量组合复用 DSH 公开客户端、事件与会话能力；带 UI 插件逐项评估适配，流式数据由适配层处理。不承诺任意未来插件零适配；不依赖上游私有 core 导入，不静默 fork 上游。
I5-RUNmacOS 开发、Linux 单机最终验收；PostgreSQL 使用本机 Docker 独立容器和命名卷，开发 / 测试库分开，loopback 监听。DSH 仍项目级本地进程。替代 D-DB 中平台 PG 必须为本地服务进程的表述；数据库 Docker 不改变 DSH 容器化可选及 R-A 边界。

3.2 必须携带的残余风险

R-A（C1，用户明确不追认）：无 Docker 档下，AI 子进程与 sources/ 在同一台主机、同一内核，隔离依靠 OS 用户 / 目录权限 + DSH 自带 bwrap / Seatbelt + rdws-policy 路径守卫。而 SAFETY.zh.md 明确「沙箱、审批与权限控制不保证隔离」「不得作为不可信工作负载唯一的安全控制」。用户未追认「生产 / 不可信负载必须启用 Docker 强隔离档、PoC 验收含该档」这一修订，因此：无 Docker 档仅作为开发与功能验证档，不作为生产或不可信工作负载的安全边界；面向真实项目组或生产数据时的隔离强度由部署方自行评估并承担风险，PoC 不覆盖生产档验收。台账 v3 撤回 v2 里越界的「不可推翻前置」表述，恢复自洽。
R-B（D2 口径）：关闭 dsh_session_log 与遥测只是移除附加字段与旁路通道，模型请求本身仍携带源码片段、命令输出与文件内容。若部署方选公网供应商，等同于源码出企业边界。这是用户明确选择的「平台不预设限制」的后果，不是遗漏；平台不代为判断合规性，但必须在部署清单中显著登记并要求数据合规确认。抓包验收保留为部署方检查项。
评审已确认非缺陷：D9↔D26、D7↔D26 属「当前形态 vs 未来上界」，非互斥；「默认内网网关模板 vs 不预设限制」是示例而非硬限；全 TS 单栈与长期环境分支属取向。上轮报告 §2 的其他 P0（MIT / 商标 / 第三方依赖 / 会话日志上传 / 遥测 / 锁版本）均已落到执行细则。
